# Circuit：复核通过、文件修复与验证完成是不同结果

`circuit-fibsqrt` 要求生成少于 32,000 行的门电路，计算
`fib(isqrt(N)) mod 2^32`。本例固定 Terminal-Bench 2.1 revision
`12b7565679ce5006230b820666353673a133db93`，模型返回版本
`deepseek-v4.1-flash-1017`，HIGH，官方 agent 时限 3,600 秒；五组分别在联网和
禁网条件运行一次，共十条记录。模型请求使用流式传输，Deep Agents 使用
`native_tool_images_v1` 适配器；模型调用上限 500 次，由 actor 和 grader 共享。

九条提交通过全部三项官方测试。禁网默认组通过两项，失败原因是
`gates.txt` 恰好有 **32,000 行**，违反官方严格小于 32,000 的约束。
该结果来自官方测试断言，不是根据模型自述推断。

## 禁网证据组：门禁拒绝后，改变的是什么

第一轮，评审模型输出 `satisfied`，但确定性门禁拒绝该候选。七次执行检查中，
五次退出码为 0，两次被记录为失败：

- 一次较大的 Python 参考计算和模拟器检查超时，退出码 124，没有完整结果。
- 另一次命令以 `grep -vcE ... /app/gates.txt` 结尾，输出 `0`，表示没有格式
  不匹配的行；此时 grep 返回 1。门禁按非零退出码拒绝，不能将这个退出码
  解释成电路格式错误。该命令中还出现了不存在的临时二进制文件提示。

同一轮随后已有 40 个输入零不匹配和格式检查通过的记录，但当前门禁要求候选
关联的执行检查全部通过，因此仍保留先前失败。门禁给 actor 的原因是
“检查失败或改变了声明文件”的合并提示。

actor 第二次提交时把原因解释成“多留了生成器文件”，移动了生成器并整理文件
元数据。这一解释和门禁的实际拒绝依据不同；不能把 actor 的归因当成诊断结果。
第二轮 grader 三次执行检查全部通过，其中一条明确输出
`checked 219 mismatches 0`；语义判断再次为 `satisfied`，门禁这次接受。

两轮证据中所有 `gates.txt` 的检查前后哈希均为：

`19dbc9109883739d8c0cdd8b6a02e15b2285d0419f7ef1b938a98ea11b89a266`

文件始终为 222,602 字节、8,254 行。被检查的原始 `sim.c` 哈希也没有变化。
最终文件通过官方 3/3。这里有充分证据支持“完成了更明确的重新验证”，没有
证据支持“第二轮修复了错误的电路”。整个目录确有辅助文件调整，因此也不把
“电路文件相同”扩大为“整个工作区未变”。

## 复核的收益和成本

禁网证据组共 109 次模型响应，其中 actor 94 次、grader 15 次。grader 消耗
170,516 输入 token、7,058 输出 token，共执行十次验证检查、产生两轮候选。
这些消耗已计入上表，不能额外叠加。联网证据组一次复核通过，grader 为 9 次
响应、142,474 输入 token、5,156 输出 token、六次验证检查。

联网文本 rubric 只用一次 grader 响应，消耗 6,087 输入 token、649 输出 token，
根据轨迹给出通过；其最终提交同样通过官方评分。禁网文本 rubric 没有产生候选，
grader 调用为零，最后由时限结束，因此不能用这一条衡量实际复核质量。

这个例子展示了证据门禁确实会独立于语义评审做决定；同时也暴露了验证命令
退出码约定和反馈精度的重要性。一个正确输出 `0` 的 grep 计数、一次超时检查，
都可能引发额外修复循环，而笼统原因可能让 actor 改动无关辅助文件。
后续改进假设是明确区分业务失败、检查未完成和执行约定，并反馈具体失败证据。
本轮冻结配置保持不变，结论留到全量分布中检验。

mini 在两个网络条件都通过，且该题调用量和耗时低于四个 Deep Agents 组。
十个条件各只有一次运行；该题的组间差异不能单独证明网络或 rubric 的因果
收益。这也不是 reward hacking 的已证实案例：当前记录说明的是评分约束、
验证失败及归因之间的差别。
