# COBOL：先交付可运行实现，再扩展验证

`cobol-modernization` 要求把已有 COBOL 程序改写为 `/app/program.py`，保留文件操作和计算行为。
本例使用 Terminal-Bench 2.1 revision `12b7565679ce5006230b820666353673a133db93`，
DeepSeek 返回版本 `deepseek-v4.1-flash-1017`，HIGH，官方 agent 时限 900 秒。
五组各在联网和禁网条件运行一次，共十个单元；使用流式响应及既定原生工具适配。

mini 的两个提交均通过全部 3 项官方测试。八条 Deep Agents 记录均在时限到达时结束，
通过 1 项、失败 2 项。官方失败断言直接指出 `/app/program.py` 不存在，随后运行该路径也失败。
十条记录的提交传输和实例回收均已验证。

## 轨迹解释

mini 在禁网轨迹的第 14 次工具调用、联网轨迹的第 11 次工具调用写入 `/app/program.py`。
随后建立 COBOL 与 Python 的差分测试，比较输出文件，并修正账户更新、短记录读取等行为。
联网轨迹中可以看到先将短记录理解为补空格，随后依据差分结果改为保留记录缓冲区未覆盖的内容。
最终的官方 3/3 分数来自保留的提交，而非模型声称测试通过。

Deep Agents 的轨迹则持续在 `/tmp` 构造小型 COBOL 程序，检查固定长度记录、数字字段移动和文件更新行为。
例如，禁网默认组临近时限仍在生成 `h.cbl` 探查数字字段；禁网文本 rubric 组还在分析 2,560 组字节实验结果。
这些操作在研究源程序语义，但在本题的 900 秒预算内，没有推进到生成要求的 Python 文件。
联网默认组曾编写 `/tmp/harness.py`，其中提到了 `program.py`，这只是测试脚手架；官方评分仍确认目标文件不存在。

八条 Deep Agents 记录中，候选提交数、grader 调用数和证据检查数均为零，也没有生成 review 记录。
因此这个案例定位的是候选提交前的任务推进问题，不能从这些分数估计已执行 rubric 复核的质量。

## 成本与后续假设

mini 在本题使用更少的模型响应、更少的输出 token，并在时限内交付。它的所有成本维度并非都更低：
禁网 mini 累计输入 2,005,675 token，高于禁网默认组的 1,098,115 token，且两者均有较高缓存占比。
禁网默认组输出 150,404 token，其中 134,502 是推理 token；更长的推理与更多工具活动未转化为可评分实现。

值得在后续独立实验检验的改进是：较早形成可运行版本，限制边界行为探索的预算，并为修复和复核预留时间。
当前全量实验保持冻结配置，不据此修改已开始的模型单元。联网与禁网的十条记录呈现相同胜负格局，
这一题不足以估计网络效果，也没有证据把本次失败归为 reward hacking。
