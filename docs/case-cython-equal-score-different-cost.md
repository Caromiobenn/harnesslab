# Cython：相同官方得分，不同执行成本

本例来自六题矩阵中禁网的 `build-cython-ext`，模型为
`deepseek-v4.1-flash-1017`，推理强度 HIGH，每组独立运行 1 次，官方执行预算
900 秒。五组都通过了官方 11 项测试，reward 均为 1；调用量、结束行为和耗时
却有明显差别。

| 组别 | 模型响应 | 工具调用 | 输入 token | 输出 token | Actor 耗时（秒） | 结束方式 |
| --- | ---: | ---: | ---: | ---: | ---: | --- |
| mini | 30 | 47 | 1,049,763 | 14,529 | 249.7 | 主动提交 |
| deepagents_default | 123 | 156 | 5,849,368 | 84,715 | 898.2 | 到达时限 |
| generic_retry | 107 | 137 | 3,247,614 | 35,713 | 898.2 | 到达时限 |
| rubric_transcript | 164 | 200 | 9,065,707 | 90,743 | 898.3 | 到达时限 |
| rubric_evidence | 153 | 175 | 6,987,165 | 92,885 | 897.2 | 到达时限 |

token 或美元成本。原始指标保留了各部分，可按实际价格另外计算。

mini 的轨迹在检查全局安装、扩展模块和示例结果之后，通过
`COMPLETE_TASK_AND_SUBMIT_FINAL_OUTPUT` 主动提交。四个 Deep Agents 组的
Harbor 记录则是 `AgentTimeoutError`；最后仍在发出工具调用。例如默认组继续
修改 `periodic.py` 的导入，普通复查组重新构建 wheel，文本 rubric 组继续检查
Cython 生成代码，证据 rubric 组继续查看 knot invariant 的实现与已有异常。
这些是轨迹中的实际操作，不表示每一步都影响官方评分。

超时后保留的最终文件通过了全部官方测试，所以这四条仍按成功计入主实验。
“官方得分为 1”和“正常结束”是两个独立指标。当前证据没有给出中间版本的
官方评分，因此不能据此确定它们何时第一次达到 11/11，也不能把后续所有工作
都认定为无效。

四个 Deep Agents 组记录到的模型响应结束原因全部是 `tool_calls`，候选提交数
均为 0；两个 rubric 组的 grader 调用均为 0，`review_outcome` 为空。这次没有
进入候选提交后的复核环节，因而不能用评分器反复复核解释额外成本，也不能用
该题证明 rubric 改善或损害了准确率。它揭示的是当前候选提交触发机制：actor
持续使用工具时，提交后的复核还没有机会介入。

可由本例提出后续假设：以任务要求组织自测、明确完成条件和及时提交，可能
降低同分情况下的调用开销。当前配置继续冻结，本轮结果不因这个观察而重跑。
每组只有 1 次运行，后续需要结合全量任务分布检验这一现象是否普遍。

五组的提交归档均通过传输校验，官方测试记录和实例回收结果已保存。证据索引
为 `artifacts/coding-reports/pilot-v2/cython-case-evidence.json`，记录各组 outcome、
轨迹、提交清单和官方测试文件的路径及 SHA-256。原始批次为
`artifacts/coding/tb21-high-offline-v2-20261114/`。
