# 内存堆修复：文字复核的误拒绝与追加成本

`custom-memory-heap-crash` 的禁网 `rubric_transcript` 试次最终通过官方 6/6 项测试。
但文字复核器的第一次拒绝包含两处判断偏差：把并非原有文件的 `/app/core` 当作原有文件，
并把官方测试明确忽略的 `still reachable` 内存要求清零。首个候选之后又消耗了
33 次模型响应、47 次模型发出的工具调用和 74,011 个输出 token。

这个案例适合解释：最终通过与复核判断正确，需要分别核验。

## 任务与实际反馈

任务要求修复只在 Release 模式崩溃的 C++ 程序，只允许修改已有文件中的 `/app/user.cpp`，
并要求 Valgrind 检查没有内存泄漏。官方测试覆盖受保护文件内容、两种构建、两种直接运行及泄漏检查。

首个候选报告已经修复崩溃。复核器返回 `needs_revision`，给出两条主要理由：

| 复核器的判断 | 实际核对结果 |
| --- | --- |
| 删除 `/app/core` 违反了不得修改其他原有文件的要求 | 试次开始时保存的 `/app` 基线只有目录和 `main.cpp`、`user.cpp`、`user.h`；没有 `/app/core`。最终提交也没有删除任何原有路径 |
| 73,728 字节 `still reachable` 表示没有证明无泄漏，需做到零残留 | 固定版本的官方测试使用 `--errors-for-leak-kinds=definite`，源码明确说明忽略静态链接 libstdc++ 的 `still reachable` 和 `possible` 情况 |

这里的文件判断由评测控制器在模型开始前保存的基线核对；泄漏口径来自原始官方测试源码，
不是根据模型的最终解释反推。

收到拒绝后，actor 查询原始文件基线、检查异常内存池、修改 `user.cpp`，在 `user_cleanup()`
加入 `__gnu_cxx::__freeres()` 调用，并重新编译、运行和检查 Valgrind。它还恢复了 `user.cpp`
的所有权信息。第二次复核返回 `satisfied`，随后官方测试全部通过。

最终归档核验确认：只改变了已有文件中的 `/app/user.cpp`，没有删除原有路径；新增路径为
两种构建的输出文件。归档中的代码确实包含 `__freeres()`，内容哈希与提交清单一致。

## 首次候选前后的消耗

下表按轨迹中的候选边界和 actor / grader 角色划分；输出 token 包含推理 token。

| 阶段 | 模型响应 | 工具调用 | 输入 token | 输出 token | 推理 token |
| --- | ---: | ---: | ---: | ---: | ---: |
| 首个候选前的 actor | 85 | 102 | 2,502,327 | 101,862 | 87,534 |
| 第一次 grader：拒绝 | 1 | 1 | 7,653 | 23,669 | 23,362 |
| 拒绝后的 actor | 31 | 45 | 1,961,824 | 45,814 | 37,763 |
| 第二次 grader：接受 | 1 | 1 | 7,871 | 4,528 | 4,376 |
| 合计 | 118 | 149 | 4,479,675 | 175,873 | 153,035 |

首个候选之后的合计为 33 次响应、47 次工具调用、74,011 个输出 token。其中 grader
用了 28,197 个输出 token，actor 用了 45,814 个。第一次 grader 的单次输出就有
23,669 个 token，因此单看“只多了一次复核调用”会掩盖实际开销。

该阶段还生成了 6,727 个可见文本字符、269,739 个推理文本字符和 17,832 个工具参数字符。
两个候选之间相隔 469.2 秒；这个时间包含第一次复核及后续 actor 操作，不包含第二次复核。
完整 agent 耗时为 1,266.0 秒。

## 这个案例支持的结论

复核器的两条主要拒绝理由与保存的基线或官方判定口径不一致，且反馈确实触发了后续操作。
最终官方通过不能反过来证明这次拒绝提升了准确率。首个候选没有独立官方评分，
所以本案例不宣称它原本已经 6/6，也不把后续所有操作都算成无效工作。

在比较 middleware 时，应同时记录拒绝理由是否成立、文件实际变化、复核后的额外成本和最终官方结果。
对原有文件的约束可以用开始时的文件清单核对；对检测工具的警告，应区分任务要求、检测含义和评分器口径。
这些分析用于解释已有实验，本次案例整理没有改变冻结的 actor 或 grader 提示词。
