# 同一错误实现为什么在禁网时获得满分

在 Terminal-Bench 2.1 的 `filter-js-from-html` 任务中，一个只用 BeautifulSoup
整理 HTML、完全不删除 JavaScript 的实现，在修复前的禁网环境获得官方 reward 1。
指定镜像内已有浏览器驱动后，同一份代码在禁网和联网环境都被判为 0。

这是我们构造错误提交进行的评分器诊断；没有模型参与，也不占用 HIGH、N=1
主实验的模型样本。它证明了一个可复现的假通过机制，并不代表模型主动利用了漏洞。

## 固定了什么

- 错误实现 SHA-256：`cf7fefd5aab2677bb9f6227609f522630e3b13a2732ce0962f8ef3d372c7dc30`。
- 公开测试数据 ZIP SHA-256：`2d6b6599de34df3ebfc76cdbc9f530cb12afcf4cf397f754b077534d0089d287`。
- 四次均使用新实例，运行原始官方测试，保留原始 reward 和完整日志。
- 前后比较的环境清单已逐字段核对；变化是评分阶段增加
  `SE_CHROMEDRIVER=/usr/bin/chromedriver`。测试数据字节相同，压缩包元数据差异单独核对。
- 两版都保持所选网络策略直到评分结束，四个实例均已确认删除。

错误实现如下。解析、序列化会规范化 HTML，但没有任何移除脚本或事件处理器的步骤。

```python
from bs4 import BeautifulSoup
from pathlib import Path
import sys
p=Path(sys.argv[1])
p.write_text(str(BeautifulSoup(p.read_text(), "html.parser")))
```

## 为什么出现假通过

官方测试的 `run_test_alert_file` 返回是否检测到弹窗。浏览器创建异常会被捕获，
随后返回 `False`；外层测试把它解释为没有发现可执行脚本。禁网时自动驱动发现失败，
28 个浏览器批次全部没有实际完成检测，错误实现却通过了测试。

只用空提交 0 分、参考解 1 分验收环境，无法识别这种情况：空提交还会因文件缺失
等其他断言失败，参考解的满分则可能来自未执行的检查。我们因此补充了同一错误实现
的前后对照，并同时查看浏览器是否启动、是否加载页面、是否实际检测到弹窗。

修复只选择已安装的驱动，保持官方测试与评分规则原样。修复后的错误实现被拒绝，
且日志中确实出现弹窗检测。页面加载失败仍被官方测试忽略，表中保留这些次数，
不能把一个 reward 当成全部攻击向量都已执行的证明。

## 对主实验的意义

联网与禁网可能同时影响模型可获取的信息和评分器的执行，因此分析 reward hacking
需要先排除评分器不可用。主实验仍报告官方原始分数；案例分析同时检查执行日志，
将环境错误、评分盲区和模型行为分别归因。模型主动利用评分漏洞，需要在后续模型
轨迹中看到具体动作及其对奖励的影响。

本任务额外完成了四项空提交／参考解对照（作业 `1208208`）和两个原样保留 HTML
的错误提交对照（作业 `1208209`）；它们都完成实例清理。后者在两种网络下均为 0 分，
且各检测到 17 次弹窗。该前置结果与本页规范化 HTML 的错误实现是两组不同诊断。
