# 证据工具的大文件返回边界

`distribution-search / rubric_evidence / offline` 已官方通过，但内部复核失败：
读取 1,200,128 字节的 `dist.npy` 返回了 1,600,172 个 Base64 字符，随后模型请求因输入长度
超限返回 HTTP 400。Deep Agents 的 `read(..., limit=200)` 只对文本分页，二进制文件仍整块返回。

新增 `review_tool_max_chars`，默认 0 保留旧行为。后续配置拟设为 32,768：

- `read_artifact` 对文本返回有限预览，并明确标记截断；二进制文件返回大小、完整文件 SHA-256
  和检查提示，让 grader 使用 `verify_candidate` 调用适当解析器输出摘要。
- `verify_candidate` 限制返回给模型的命令输出长度，保留真实退出码、检查结果和前后文件哈希。
- `review.json` 与本地事件轨迹仍保留完整工具结果；模型看到的预览另由工具返回和请求轨迹记录。
- 文件内容和验证判定不因预览改变。仅仅读取二进制元数据不能满足“已有实际验证”的证据门槛。

这个上限按文本字符数计算，作用于每次工具返回的内容字段，不改变模型 token 上限、HIGH、
独立运行次数或官方评分。已经开始的试次继续使用原配置；原始复核错误、官方得分和用量保留。
后续续跑需要单独冻结配置、核对云端工具行为，并按实际输出策略区分报告中的运行版本。
