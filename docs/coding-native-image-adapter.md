# Native image transport for DeepSeek V4.1

The first streaming cohort exposed an adapter failure in `chess-best-move`: `langchain-deepseek==1.1.1` serializes list-valued tool content as JSON text. Deep Agents returns images from `read_file` as media blocks, so their base64 bytes became text tokens. One failed default trial recorded 978,278 input tokens on its last successful response, then received `Range of input length should be [1, 1000000]`. Its 48 successful responses accumulated 23,009,409 input tokens, including 22,023,936 cached tokens. The stored actor trajectory and submission remain unchanged.

The [Aliyun model documentation](https://help.aliyun.cn/zh/model-studio/deepseek-v4-1-flash) specifies text/image input and a 1,000,000-token input/context ceiling for `deepseek-v4.1-flash-1017`. `MultimodalChatDeepSeek` preserves the existing SDK's reasoning, tool-text and usage handling, while moving image blocks into a user message immediately after the complete group of tool results. Tool call IDs and textual outputs are preserved. The model profile declares supported modalities and applies the provider's input ceiling; the actual profile is stored in trial metadata.

This is an explicit adapter revision. Completed actor attempts, their costs and original errors are retained. Further model trials require a successful non-benchmark image canary and a recorded cohort amendment. The native mini baseline retains its own shell-tool behavior. Image-dependent tasks must be identified in interpretation because the two harnesses expose different native tools.
