# 按同一任务比较结果与成本

全量评测进行中，各组完成的题目集合可能不同。`report_coding_pairs.py` 从已冻结的全量报告中，
只选两侧都已有官方分数的同一任务、同一 repeat 进行配对，再汇总胜负和成本差。
默认组与 mini 对比，其余三个复核组分别与默认组对比；每组还配对联网与禁网运行。

```bash
python scripts/report_coding_pairs.py \
  --report /absolute/campaign-snapshot/report.json \
  --report-sha256 <snapshot-sha256> \
  --output artifacts/coding-reports/paired-snapshot
```

输出包括完整的 `pairs.json`，以及四个可直接分析的 CSV：

| 文件 | 用途 |
| --- | --- |
| `coverage.csv` | 每项比较的计划配对数与已评分配对数 |
| `comparisons.csv` | 同题胜负、双通过、双失败、任务列表和运行配置 |
| `costs.csv` | 各指标的观测总量、均值、中位数、P90 和配对差值 |
| `pairs.csv` | 每对分数、指标差、原始 trial 路径和评分来源 |

所有差值统一为“比较组减基线组”；网络差值为“联网减禁网”。
成本覆盖模型响应、工具调用、环境命令、输入/缓存/输出/推理 token、三类输出字符、
Agent 阶段和整体耗时、提交归档耗时、候选数、证据检查数，以及 grader 用量。
Agent 阶段耗时包含复核，区别于环境准备和官方评分。

每个配对单元会累计该单元所有已结束尝试的已观测成本，包括先前环境失败。
没有官方分数的尝试不产生第二个分数；已保存提交的重新评分沿用原来的 actor 消耗。
报告不启动模型、不修改原始结果。原始全量报告仍保留尚未能配对的运行和全部成本。

同一指标必须两侧都存在观测值，才计入它的比较分母。缺失值保留为空，
同时列出缺失该指标的尝试数、usage 不完整和 usage 状态未上报的尝试数。
例如，取消中的模型请求可能没有返回 usage；记录的 token 是已收到的用量，不能当作完整账单。
输入 token 包含缓存部分，输出 token 包含推理部分，不能再相加。

汇总按两侧的响应传输、工具适配器、实际模型配置分别分组，保留阶段间配置差异。
每个单元仍为一次独立运行；配对结果用于描述已完成题目的差异和定位案例。
解释某个组为什么更好时，还需要检查原始行为、文件变化及官方验证结果。
