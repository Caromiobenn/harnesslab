# Python 工具修复后的实验续跑

在缺少系统 Python 的镜像中，原生文件工具和证据指纹命令需要使用 controller 已固定的
Python。新增配置 `actor_python_fallback: true` 只用于尚未启动的单元，所有已开始试次的
得分、失败和消耗均保留。

`prepare_coding_python_continuation.py` 从已取消的待运行单元清单生成新 study：

- 逐个检查旧 study、配置、代码和缓存哈希；已创建执行目录的单元不能迁移。
- 保留原有题目、组别、网络、HIGH、N1、时间预算和模型设置，唯一 prerequisite 变化是开启 fallback。
- 在新目录保存配置、控制来源和旧单元映射，继续使用原来的单元运行器。
- 云端验收要求禁网和联网的文件／证据工具探测成功、实例回收完成，并通过四个 empty/oracle 对照。
- 控制复用保留每题原有的四个官方结果，并单独引用这次运行依赖变更的验收记录。缓存、提交路径等其他字段不能借此变更。

报告从试次保存的 `network.json` 读取实际开关值。运行版本汇总和配对成本比较按该值分开，
避免把修复前后的工具可用性混入同一运行版本。全矩阵总览仍保留全部试次及原始消耗。

启用新队列前，核对被替换的 Slurm 单元均未启动且已取消；正在运行的旧单元继续执行，新队列
通过依赖关系等待其结束。每个新单元使用独立目录，沿用最多两个并行控制器。
