# 第二轮实验协议

第一轮的 36 个首份候选均达标。本轮使用四个输入规则更复杂的终端任务，观察解决方案、约束满足和复查的变化。

| 因素 | 两个条件 |
| --- | --- |
| 产物要求 | 语言任选，或交付 C 源码与可按指定命令重建的二进制 |
| 工具链 | 已配置，或参照本地文档选择、解包和配置同一个编译器 |

四项任务分别覆盖跨时区聚合、CSV 对账、先进先出库存模拟、带并行边的最短路径计数。功能检查由独立参考逻辑生成。两个工具链条件使用相同编译器和构建参数。空提交和正确参考解覆盖全量 16 个任务条件。

先运行 **8 次校准**。每题在预装条件下测试两种产物要求，各一次，直接交付首份候选。校准使用独立评分种子 `18017`，检查实际工具调用、容器、评分、公开检查和任务难度。校准与正式结果分别保存。选择在校准后修改任务时，重新记录协议和对照。

正式矩阵 **4 × 2 × 2 × 3 = 48** 次，评分和调度种子均为 `18053`。固定阿里云百炼 `deepseek-v4.1-flash-1017`、关闭思考模式、温度 0.3、每次响应最多 4096 个 token、整条轨迹最多 20 次模型响应，首份候选后最多四次复查响应。控制器在两次请求之间检查 210 秒软时限。固定版本以 `design.json` 内的镜像 ID 和评分器与 runner 哈希为准。

正式矩阵的终版主要指标是强制 C 条件中功能通过但明确缺少交付要求的比例，以有可用最终评分的全部尝试为分母。按题、条件和产物类型报数。来源无法确认的提交保留单独状态。无可靠评分的链路异常单列。

正式轨迹完成后，从同一条轨迹评估三种交付策略。

1. 直接交付选择模型的首份候选。
2. 固定复查选择执行统一复查后的终版。
3. 按需复查先检查首份候选的公开样例和可公开核验的交付要求，失败或缺失时选择终版，其余选择首份候选。

公开检查发生在模型运行结束后，由独立容器对冻结的首份候选执行。模型能看到检查所用的公开输入输出和交付约定。私有功能评分在隔离容器中离线执行。按需复查的成本由选中端点的累计用量加公开检查耗时计算。三种策略的比较适用于相同前缀、相同复查提示和可比较的首份、终版、公开门禁，使用完整配对分母并单列无法配对的轨迹。节省的预算在该比较中没有前移到解题阶段。

历史审计的第二轮使用已有原始证据的脱敏摘录，报告自然案例和诊断对照。此前的 171 次判断是结构化节录基线。
